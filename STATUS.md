# VimKit: состояние проекта

Обновлено: 15 ноября 2026, версия 0.2.1.

VimKit — Swift Package, который добавляет Vim-раскладку в нативные текстовые
вьюхи на macOS и iPad. Ядро — движок codemirror-vim (`vim.js`, MIT), он без
изменений работает в JavaScriptCore за собственным адаптером в стиле
CodeMirror 5. Подробности по API — в [README](README.md), история
версий — в [CHANGELOG](CHANGELOG.md).

## Что сделано

### Движок (`VimCore`)

- `VimEngine`: отдельный от UI движок. Принимает клавиши, правит текст и
  сообщает обо всём делегату.
- Режимы: normal, insert, replace, visual (посимвольный, построчный,
  блочный).
- Движения, операторы, текстовые объекты, включая теги.
- Регистры, включая `+`, который работает с системным буфером обмена.
- Макросы, метки, счётчики, повтор через `.`.
- Поиск с подсветкой.
- Ex-команды: `:s`, `:g`, `:sort`, `:normal`, `:map` и другие.
- Undo и redo с группировкой.
- Свои ex-команды через `defineEx`; `:w` вызывает колбэк сохранения.
- Не латинские раскладки: команды берутся по физическим клавишам.
- Учёт синтаксиса:
  - `%` и кавычечные текстовые объекты пропускают скобки в строках и
    комментариях. Источник — `vimEngine(_:tokenTypeAt:)`, атрибут
    `.vimTokenType` или `tokenTypeProvider`.
  - `=` расставляет отступы по глубине скобок.
- Фолдинг:
  - Команды: `zc`, `zo`, `za`, `zM`, `zR`, `zf{motion}`, `zd`, `zE`.
  - Блоки ищутся по отступам. Закрывающая скобка на уровне заголовка входит
    в блок.
  - `j`/`k` перескакивают свёрнутый блок. Построчные операторы (`dd`, `yy`,
    `>>`, `3dd`) и `V` берут блок целиком. `o` вставляет строку после блока.
  - Поиск, метки, `%` и undo внутрь блока его разворачивают. `G`, `gg`,
    `<C-d>`, `H`/`M`/`L` оставляют блок свёрнутым и ставят курсор на его
    заголовок.
  - Правки внутри блока его не удаляют. Блок удаляется только правкой через
    его первую или последнюю строку.
  - Для своих хостов: `VimEngine.folds` и `vimEngineFoldsDidChange(_:)`.

### Вьюхи (`VimKit`)

- Три вьюхи:
  - `VimTextView` — своя вьюха на `NSView`: раскладка `VimTextLayout`
    (точная высота каждой строки, дерево Фенвика), отрисовка видимых строк
    через CoreText, ввод через `NSTextInputClient` (IME, диктовка),
    стандартные команды редактирования, меню «Правка», мышь, доступность;
  - `VimUITextView` — `UITextView` на TextKit 2, для iPad и iPhone;
  - `VimEditor` и `VimStatusLine` — для SwiftUI на macOS и iOS.
- Блочный курсор инвертирует символ под собой. На концах строк рисуется
  блок.
- Подсветка поиска.
- Движения по экранным строкам: `<C-d>`/`<C-u>`/`<C-f>`/`<C-b>`, `zt`/`zz`/`zb`,
  `H`/`M`/`L`, `gj`/`gk`/`g0`/`g$` при переносе строк.
- Свёрнутые строки скрываются через делегат хранилища текста. После
  заголовка показывается плашка «⋯ N lines».
- iPad:
  - аппаратные клавиши с автоповтором при удержании;
  - `Ctrl-[` или Caps Lock в роли Esc;
  - с экранной клавиатурой в normal-режиме буквы работают как команды;
  - `⌘Z` / `⇧⌘Z` используют историю Vim.
- Правки со стороны вьюхи (ввод, вставка, диктовка, IME) доходят до движка.

### Качество и скорость

- Тесты codemirror-vim прогоняются через адаптер: **714 из 716**. Два
  оставшихся провала — сознательные отличия, они перечислены в
  `Tests/VimCoreTests/Resources/upstream-known-failures.txt`:
  - `dat` в коде на JavaScript;
  - `<C-c>`, который в браузере копирует.
- Свои тесты: движок, свёртки, раскладки клавиш, сценарии в настоящем окне
  macOS, `VimUITextView` на симуляторе iPad.
- Тесты производительности. На файле в 20 000 строк (1 МБ) большинство
  команд укладывается в 5 мс на клавишу. Первый `G` занимает около 0,25 с,
  `:%s` вместе с undo — около 1 с.
- Стенд производительности `swift run -c release VimKitBench`: около 90
  операций на уровне движка и вьюхи. По каждой — время (медиана, p95,
  максимум, первый запуск), CPU, инструкции, энергия (оценка), пик и
  удержанная память, кадры дольше 16,7 мс. Результат — JSON и HTML-отчёт
  в `bench-results/` со сравнением с прошлым прогоном.
- Поиск блоков свёрток вынесен из JavaScript в нативный код и сравнён на
  стенде на двух языках (прогоны 8 и 9, 20 000 строк): Swift 0,62 мс,
  Goose 0,67 мс, JavaScript 13 мс. В библиотеке — Swift
  (`VimRuntime.foldKernel`, можно вернуть `.javascript`). Goose остался
  только в стенде и тестах: его рантайм ставит обработчики SIGSEGV/SIGBUS,
  библиотеке это ни к чему.
- Отступы `>`, `<`, `=` по многим строкам: колонки считает Swift
  (`VimIndentKernel`), строки меняются одной пачкой (`$applyChanges`); undo и
  redo больших правок — тоже пачкой; многострочные правки больше не
  перестраивают индекс строк. 20 000 строк, движок (прогоны 9 → 11):
  `ggVG>` 101 → 14 мс, `ggVG=` 60 → 4 мс, `:g/note 5/d` 155 → 13 мс,
  `u` после `:%s` 43 → 7 мс.
- Своя отрисовка на macOS (прогон 12): вьюха теперь стоит почти столько же,
  сколько движок. 20 000 строк, прогоны 11 → 12: первый `G` 285 → 0,3 мс,
  `ggVG>` 367 → 16 мс, `ggVG=` 151 → 4 мс, `:%s` 463 → 124 мс, `zM`
  35 → 21 мс; весь прогон стенда 46 → 19 с. Высота документа точная и не
  меняется при прыжках (`documentHeightIsExactAndStable`).
- Известный артефакт стенда: с прогона 10 `t"` в полном прогоне (движок,
  20 000 строк) — 0,5 мс вместо 0,1. Отдельно и в частичных прогонах — 0,1.
  Зависит только от того, что у хоста на одну функцию больше (indentPlan),
  даже если её не вызывать; принудительная сборка мусора между сценариями
  не помогает. Похоже на кеши интерпретатора JavaScriptCore, а не на код.
- CI на GitHub Actions: `swift build` и `swift test` на macOS, тесты на
  симуляторе iPad, сборка iPad-демо.
- Демо: `swift run VimKitDemo` на macOS и `Demo/VimKitDemo.swiftpm` для
  iPad. В обоих есть образец на 20 000 строк и открытие любого файла.
- Релизы: 0.1.0, 0.2.0, 0.2.1.

## Что предстоит сделать

### Своя отрисовка вместо TextKit 2

TextKit 2 держит раскладку только около экрана, а высоту остального текста
оценивает (20 000 строк: 380 тыс. pt при настоящих 320 тыс.) и при
прокрутке снова переоценивает уже разложенное — бегунок меняет масштаб и
прыгает, а точная раскладка от начала файла делает дальние переходы после
правок медленными (~265 мс). Хуков, чтобы это исправить, до macOS 27 нет.
Решено: своя модель строк и своя отрисовка видимого, имена и основной API
`VimTextView` / `VimUITextView` сохраняются.

- [x] Модель строк `VimTextLayout` (общая для macOS и iOS): индекс строк,
  число экранных строк у каждой (перенос через CoreText, быстрый путь по
  ширине глифов для тех, что влезают), свёртки как ноль строк,
  `y ↔ строка` через дерево Фенвика, геометрия символов; правки обновляют
  её по месту. 20 000 строк (release): построение 1,6 мс, правка в начале
  и прямоугольник символа в конце 0,64 мс, замена всего текста 4,5 мс.
- [x] macOS: своя вьюха — отрисовка видимых строк, курсор, выделение,
  подсветка поиска, плашки свёрток, ввод через `NSTextInputClient` (IME),
  мышь, буфер обмена, доступность; точная высота документа. Прогон 12.
- [ ] iOS: `UITextInput` + `UITextInteraction` (системные ручки, лупа,
  меню), аппаратные клавиши.
- [x] macOS: `VimEditor`, демо, стенд, документация; прогон 12 в истории.
- [ ] iOS: `VimEditor` на новой `VimUITextView`, прогон стенда.

### Фолдинг

- [ ] Другие способы находить блоки: по синтаксису от хоста, по маркерам
      `{{{`/`}}}`, ручной режим как основной. Сейчас блоки ищутся только по
      отступам.
- [ ] Навигация по свёрткам: `zj`, `zk`, `[z`, `]z`, `zv`, `zF`, `zn`/`zN`.
- [ ] Ex-команды `:fold`, `:foldopen`, `:foldclose`.
- [ ] Сохранение свёрток между сессиями (API для хоста).
- [ ] `:N` по номеру строки сейчас ведёт себя как предыдущее движение. Он
      должен всегда оставлять блок свёрнутым.
- [ ] Измерить `zM` на 20 000 строках. Плашки расставляются сразу для всех
      свёрток, а тест покрывает только 3000 строк.

### iPad

- [ ] Кнопка Esc и полоска с командами над экранной клавиатурой
      (`inputAccessoryView`). У экранной клавиатуры нет Esc, поэтому без
      аппаратной клавиатуры из insert-режима не выйти.
- [ ] Несколько курсоров: `UITextView` показывает только основное
      выделение.
- [ ] Обработка нажатий (`pressesBegan`) не покрыта автотестами: UIKit не
      даёт создать такие события в тесте. Проверено вручную.

### macOS

- [ ] Своей вьюхе пока нет того, что `NSTextView` давал даром: проверки
      орфографии, панели поиска `⌘F` (`NSTextFinder`), сервисов, Writing
      Tools; текст справа налево не проверялся.
- [ ] Перерисовку в живом окне (курсор, подсветка) автотесты не проверяют:
      офскрин-рендер перерисовывает всё целиком. Нужен тест через захват
      окна или ручная проверка в демо.

### Возможности Vim

- [ ] `:e`, `:q`, `:wq` и работа с файлами отдаются хосту через
      `defineEx`. Готовых команд нет.
- [ ] `'foldopen'`, `'foldmethod'` и прочие опции свёрток через `:set`.
- [ ] Чтение конфигурации (аналог `.vimrc`) при старте.
